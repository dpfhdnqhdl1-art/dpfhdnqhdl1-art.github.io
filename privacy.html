개인정보처리방침

최종 작성일: 2026년 11월 6일 · 대상: 워크메이트 1.11 계열

워크메이트(WorkMate)는 개인과 소규모 팀을 위한 Windows 프로그램입니다. 이 방침은 프로그램과 이 안내 웹사이트에서 다루는 정보, 외부 전송, 보관 및 삭제 방법을 설명합니다.

핵심 안내
Google 권한은 사용자 본인 계정으로 허용합니다. AI 채팅에서는 대화·첨부와 요청 처리에 사용된 일정·일지·Maximo 조회 결과가 설정된 AI 서비스로 전송될 수 있습니다. 대화·조회 결과·작업일지 초안과 복구 사본은 PC에 남을 수 있습니다.

1. 처리하는 정보와 이용 목적

구분처리 정보와 목적
Google 인증연결을 유지하기 위한 OAuth 접근·갱신 토큰, 허용 범위와 연결 설정을 처리합니다. Google 비밀번호는 앱이 수집하지 않습니다.
Google Calendar캘린더 이름·ID·접근 권한과 일정 제목·기간·장소·설명 등 API 응답을 읽습니다. 일정 표시·검색·추가·수정, 휴가 반영, 안전문서 생성에 이용합니다. 이름 등 개인정보가 일정에 들어 있으면 함께 처리될 수 있습니다.
Google Sheets사용자가 지정한 시트의 기록과 서식을 읽고 작업일자, 작성자 표시 이름, 위치, 작업내용·결과·비고 등 일지 내용을 처리합니다. 기록 작성·수정·삭제, 검색, Excel 가져오기·내보내기와 복구에 이용합니다.
AI 대화·첨부입력한 질문, 대화 이력, 응답, 선택한 첨부 파일 또는 추출한 내용, 도구 조회 결과를 처리합니다. 답변·파일 분석·업무 요청 처리와 대화 복원에 이용합니다. 서비스·모델별 사용량도 기록합니다.
Maximo연결한 서버의 WO·SR, 설명·작업로그·첨부 및 제공되는 자재·작업시간 정보를 읽습니다. 작업자 코드·비용 등이 포함될 수 있으며 조회·검색·요약·내보내기에 이용합니다. 현재 연동은 읽기 전용입니다.
PC 설정·문서서비스 API 키, 캘린더·시트 연결 설정, 문서 양식·서명 이미지, 저장 경로, 작성자 표시 이름, 생성 파일, 초안·복구 사본을 처리합니다. 키와 인증 토큰은 업무 내용으로 AI에 보내지 않습니다.
문의이메일로 문의하면 발신 주소와 문의 내용을 답변·문제 해결에 이용합니다. 문의에 비밀번호·API 키·인증 토큰을 포함하지 마세요.

2. Google 접근 권한

Google 로그인·동의 화면에서 허용한 계정의 권한으로 동작합니다. 앱은 기능에 따라 아래 범위를 요청합니다.

  • calendar.readonly: 연결한 캘린더와 일정을 읽어 달력, 일정 검색, 문서 생성에 사용합니다.
  • calendar.events: 사용자가 요청하고 확인한 일정 추가·수정에 사용합니다. 앱의 공휴일 연결은 읽기 전용으로 취급합니다.
  • spreadsheets: 작업일지용 시트 생성과 연결한 시트의 조회·작성·수정·삭제·서식 처리에 사용합니다.

위 범위는 Google 동의 화면상 계정에서 접근할 수 있는 여러 캘린더·시트에 대한 권한을 포함합니다. 앱에서는 설정하거나 사용자가 지정한 대상으로 기능을 실행합니다. Drive 전체 파일 검색이나 자동 공유 기능은 제공하지 않습니다.

팀원은 각자 본인 Google 계정으로 연결하며, 실제 공유 범위는 Google Calendar·Sheets의 공유 설정에 따릅니다. 앱 설치나 공용 AI 키 사용만으로 다른 사람의 개인 캘린더가 공개되지는 않습니다. 표시 이름은 직접 입력하는 값이며 신원 인증 수단이 아닙니다.

3. 외부 서비스 전송과 공유

  • Google: 일정·시트를 읽거나 변경할 때 요청과 필요한 데이터가 Google API로 전달됩니다. 공유 시트에 저장한 기록은 해당 시트의 공유 권한을 가진 사람이 볼 수 있습니다.
  • AI 서비스: AI 채팅을 전송하면 질문·대화 문맥·첨부 내용과 해당 요청에서 도구로 조회한 기록이 설정된 서비스에 전달됩니다. 후속 질문에도 이전 대화의 관련 정보가 포함될 수 있습니다. 팀 배포판은 OpenAI를 사용합니다. 일반판은 설정에 따라 OpenAI, Anthropic의 Claude 또는 Google의 Gemini를 사용합니다.
  • 단순 조회: 달력·작업일지·Maximo 화면의 일반 조회만으로 해당 내용을 AI에 보내지는 않습니다. AI 연결·기능 확인 버튼은 검사 요청을 AI 서비스에 보냅니다.
  • Maximo 서버: 연동을 켜고 조회할 때 설정한 서버로 검색 조건과 인증 정보가 전달됩니다. AI 분석을 요청하면 관련 조회 내용이 AI 서비스에도 전달될 수 있습니다.
  • 운영자: 현재 앱에는 사용자 자료를 모으는 별도 운영자 서버가 없습니다. 다만 운영자가 직접 공유받은 시트나 사용자가 문의로 전달한 자료에는 접근할 수 있습니다.

외부 서비스는 해외에서 데이터를 처리할 수 있습니다. 보관 기간·처리 지역·계정별 데이터 설정은 해당 서비스와 API 이용 계약에 따릅니다. 앱에서 대화를 지우거나 연결을 해제해도 외부 서비스에 이미 전달된 데이터가 자동 삭제되는 것은 아닙니다. 프로그램은 모든 외부 서비스에 대해 무보관이나 모델 학습 제외를 일괄 보장하지 않습니다.

워크메이트 운영자는 Google 사용자 데이터를 판매하거나 광고 타기팅에 이용하지 않으며, 범용 AI 모델의 학습·개선을 목적으로 별도 수집하지 않습니다. Google 데이터는 요청한 사용자용 기능을 제공하는 범위에서 처리합니다. AI 이용 시에는 데이터 권한과 해당 API 계정의 처리 조건을 확인해야 합니다.

참고: Google API Services User Data Policy. 이 방침을 게시하는 것만으로 Google의 앱 검증이나 승인이 완료되지는 않습니다.

4. 저장 위치와 보관

  • PC: 설정, Google OAuth 토큰, 대화와 일부 도구 조회 결과, 사용량, 작업일지 초안·수정·삭제 복구 사본을 사용자 프로필 폴더에 저장할 수 있습니다. 일반 설치본의 기본 위치는 %LOCALAPPDATA%\WorkMate이며 실행 방식에 따라 달라집니다. 자동 일괄 보관 만료 기간은 설정되어 있지 않습니다.
  • 키 보호: 데스크톱 설정에서 저장한 AI·Maximo API 키는 Windows 사용자 보호 기능(DPAPI)으로 보관합니다. Google OAuth 토큰과 대화·초안·백업 전체가 같은 방식으로 암호화되는 것은 아닙니다. 환경변수나 별도 설정 파일로 직접 지정한 값은 그 저장 방식에 따릅니다.
  • 첨부: 선택한 첨부 원본은 주로 현재 대화 메모리에서 처리하며, 일부 형식 변환에 임시 사본을 사용합니다. 저장된 대화에는 첨부 이름·분석 결과·관련 텍스트가 남을 수 있습니다. 사용자가 선택한 원본 파일은 원래 위치에 남습니다.
  • 문서: 생성한 Word·PDF·Excel 파일과 처리 기록은 지정한 출력 폴더에 보관됩니다. 앱을 종료하거나 업데이트해도 자동으로 삭제하지 않습니다.
  • Google 시트: 공유 일지는 Google에 저장됩니다. 수정·삭제 이력은 Google의 버전 기록이나 앱의 복구 사본에도 남을 수 있습니다.
  • 문의 메일: 문의 처리에 필요한 기간 동안 보관하며, 삭제 요청은 아래 이메일로 접수할 수 있습니다.

5. 연결 해제·정보 수정·삭제

  1. Google 접근을 중단하려면 Google 계정의 서드 파티 연결 관리에서 워크메이트 또는 연결 당시 표시된 앱을 찾아 접근 권한을 삭제합니다. 재동의하기 전에는 연결된 기능을 사용할 수 없습니다.
  2. 공유 일정과 작업일지는 Google 또는 앱에서 제공하는 수정·삭제 기능으로 관리합니다. Google 접근 권한을 해제하는 것만으로 기존 일정·시트 기록이 지워지지는 않습니다.
  3. PC 자료를 삭제하려면 앱을 종료한 뒤 실제 사용자 프로필과 출력 폴더를 확인합니다. 대화 및 이전 대화 사본, 조회 결과, 초안, 복구 백업, 토큰, 내보낸 문서를 필요한 범위에서 별도로 삭제해야 합니다. 새 대화 시작이나 앱 제거만으로 모든 사본이 삭제된다고 볼 수 없습니다.
  4. 외부 AI에 전달된 데이터의 삭제·처리 제한은 해당 서비스와 API 계정 관리 경로를 이용합니다. 로컬 자료 삭제나 Google 연결 해제만으로 외부 AI의 자료를 회수할 수는 없습니다.
  5. 운영자에게 문의한 자료의 확인·정정·삭제를 원하면 아래 주소로 요청해 주세요. 운영자가 보유하지 않은 PC·Google·외부 서비스 자료는 그 저장 위치에서 별도로 처리해야 합니다.
